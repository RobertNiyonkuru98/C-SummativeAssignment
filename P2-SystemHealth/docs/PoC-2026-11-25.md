# P2 - Linux System Health and Resource Monitoring Manager

## What the script does

An interactive bash script that monitors the health of the Linux system it runs
on and keeps a log of everything the user does:

```
--------------------------------------------------------------
   LINUX SYSTEM HEALTH AND RESOURCE MONITOR
--------------------------------------------------------------
   1) Display system information
   2) Monitor CPU utilisation
   3) Monitor memory utilisation
   4) Monitor disk utilisation
   5) View and search running processes
   6) Terminate a process
   7) Generate a system health report
   8) View activity history
   9) Clear the activity log
  10) Exit
--------------------------------------------------------------
```

Run it with `./systemhealth.sh`. Every action writes a timestamped line to
`$HOME/.syshealth/activity.log`, and reports are written to
`$HOME/.syshealth/reports/` unless the user chooses another directory.

### 1. How the script is organised

| Function | Job |
|---|---|
| `log_activity` | appends one timestamped line to the activity log |
| `heading` | prints the section banner |
| `confirm` | yes/no prompt used before terminating a process or clearing the log |
| `read_threshold` | reads and validates a 1-100 threshold, keeping the old value on empty input |
| `require_command` | checks a utility exists before using it |
| `show_system_info` | hostname, OS, kernel, architecture, uptime, date and time |
| `read_cpu_usage` | samples `/proc/stat` twice, one second apart |
| `monitor_cpu` | prints CPU usage, the busiest processes and the threshold check |
| `monitor_memory` | reads `/proc/meminfo`, computes utilisation, checks the threshold |
| `monitor_disk` | lists mounted filesystems and flags those above the threshold |
| `search_process` | lists the busiest processes and searches by name or PID |
| `terminate_process` | validates the PID, refuses protected processes, confirms, then sends SIGTERM |
| `generate_report` | writes a timestamped health report to a directory the user chooses |
| `view_log` | shows the last 40 log entries |
| `clear_log` | empties the log after confirmation |
| `main` | menu loop and input validation |

### 2. System information

```
  Hostname        : UTB-CFO-LAPTOP
  Operating system: Ubuntu 24.04.2 LTS
  Kernel version  : 5.15.167.4-microsoft-standard-WSL2
  Architecture    : x86_64
  Uptime          : up 16 hours, 54 minutes
  Current date    : Wednesday, 25 November 2026
  Current time    : 17:51:11
```

The OS name comes from `/etc/os-release`, the uptime from `uptime -p`, and the
date and time from `date` with a format string.

### 3. CPU utilisation

CPU usage is **calculated, not guessed**. `/proc/stat` reports cumulative jiffies
since boot, so the script reads the first line twice, one second apart, and
compares the two samples:

```
total = user + nice + system + idle + iowait + irq + softirq + steal
idle  = idle + iowait
usage = 100 * (total2 - total1 - (idle2 - idle1)) / (total2 - total1)
```

Reading the difference between two samples means the figure reflects what the
CPU is doing now, rather than an average since the machine booted. In the
captured run it reported **13%** against a 75% threshold.

The busiest processes come from `ps -eo pid,pcpu,pmem,comm --sort=-pcpu`.

### 4. Memory utilisation

`/proc/meminfo` is read for `MemTotal` and `MemAvailable`, and:

```
used percent = 100 * (MemTotal - MemAvailable) / MemTotal
```

`MemAvailable` is used instead of `MemFree` because it includes memory that can
be reclaimed from cache, which is what actually matters to the user. The
captured run reported 7818 MB total, 4488 MB used and **57%** utilisation.

### 5. Disk utilisation

`df -P` is parsed line by line to show the filesystem, size, used, available,
use% and mount point. Pseudo-filesystems (tmpfs, devtmpfs, squashfs, fuse and
the snap mounts) are filtered out so only real storage is listed. Every
filesystem whose use% is at or above the threshold is listed as a warning:

```
  Filesystems at or above the 90% threshold:
    WARNING: /usr/lib/wsl/drivers (drivers) is 99% full
    WARNING: /mnt/c (C:\) is 99% full
```

The loop uses process substitution (`done < <(df ...)`) rather than a pipe so
that the counter inside the loop survives after it finishes — in a pipeline the
loop runs in a subshell and the count is lost.

### 6. Process management

- `ps -eo pid,user,pcpu,pmem,comm --sort=-pcpu` lists the ten busiest processes.
- Searching accepts a name (case-insensitive `grep`) or a PID (exact `ps -p`).
- Terminating checks, in order: the PID is a whole number, the process exists,
  and it is not PID 1, this script's own PID, or its parent shell. Only then
  does it ask for confirmation and send `SIGTERM`.
- If the kill fails, the script says it is a permission problem instead of
  pretending it worked.

Captured behaviour:

```
  Enter the PID to terminate: 999999
  No process is running with PID 999999.

  Enter the PID to terminate: 1
  Refused: 1 is a protected process (init or this monitoring session).
```

### 7. Health report

The report is written to the directory the user types (the default is
`$HOME/.syshealth/reports`, created if it does not exist). Each file is named
`health-report-YYYYmmdd-HHMMSS.txt` and contains the hostname, kernel, uptime,
CPU threshold, memory figures, the disk table and the busiest processes.
`docs/evidence/sample_report.txt` is a real one:

```
==============================================================
  SYSTEM HEALTH REPORT
  Generated : 2026-11-25 17:54:12
  Hostname  : UTB-CFO-LAPTOP
  Kernel    : 5.15.167.4-microsoft-standard-WSL2
  Uptime    : up 16 hours, 57 minutes
==============================================================
```

### 8. Activity log

Every action is recorded with a timestamp, including warnings and refusals, so
the log is an audit trail rather than a list of successes:

```
[2026-11-25 17:53:51] Monitoring session started
[2026-11-25 17:53:58] Monitored CPU: 13% (threshold 75%)
[2026-11-25 17:54:06] WARNING: 2 filesystem(s) at or above 90%
[2026-11-25 17:54:12] Generated health report /home/robert/.syshealth/reports/health-report-20261125-175412.txt
[2026-11-25 17:54:19] ERROR: tried to terminate missing PID 999999
[2026-11-25 17:54:22] REFUSED: attempt to terminate protected PID 1
```

Option 9 clears the log, but only after a `y/N` confirmation; answering `n`
leaves it untouched (shown in the captured run).

### 9. Input validation and error handling

| Situation | What happens |
|---|---|
| menu choice is empty, a word, or outside 1-10 | "Invalid: enter a number from 1 to 10." and the menu returns |
| threshold is not a number (`abc`) | "Invalid: enter a whole number between 1 and 100." |
| threshold is out of range (`101`) | "Invalid: the threshold must be between 1 and 100." |
| empty threshold | the current value is kept |
| PID is not numeric | rejected before any system call |
| PID does not exist | "No process is running with PID …" |
| PID is 1, the script itself, or its parent | refused, and the refusal is logged |
| no permission to kill | reports the permission failure instead of claiming success |
| report directory missing | created if possible; a clear error if it cannot be |
| required command missing | `require_command` prints which utility is unavailable |

The threshold validation is visible in the captured run: `101` is rejected, then
`75` is accepted; `abc` is rejected, then `70` is accepted.
